# 책장 verify (시범판 2026-11-17)

> 출처: Claude Code 팀 글 «How the Claude Code team thinks about verification»(2026-11-16)의 «verify 스킬·3번 실패하면 사람·흔들리는 시험·검증 도장»을 효니 방식에 맞춰 옮김. 효니 말 2026-11-17 «클로드 코드 팀 검증 글 제대로 배우고 해볼래?». 시범판이라 돌려 보고 안 맞는 곳은 맨 아래 «돌려 본 메모»에 적고 본문을 고친다.

이 스킬은 **실행하는 검증**이다. 코드 읽고 따지는 일은 `REVIEW.md`(검토자가 볼 곳)와 스킬 `webapp-connect-check`(새 칸·단추 연결 점검)가 맡는다.

## 0. 어디서
- 고치는 곳은 늘 worktree(레포 `CLAUDE.md` 규칙). 공용 폴더 `웹앱\bookshelf`는 main 그대로.
- 아래 `<wt>`는 그 worktree 경로, `<out>`은 스크래치 폴더.

## 1. 시험 (늘, 약 8초)
```
node tools/run-tests.js      # = npm test, tools/test-*.js 13개
```
- 하나라도 실패하면 고친다. **다시 돌려서 초록 만들기, sleep 넣기, 시험 건너뛰기 금지.**
- 같은 시험이 이유 없이 붙었다 떨어졌다 하면(흔들리는 시험): 원인을 찾아 고치거나, 못 찾으면 그 시험을 지우고 **PR 본문에 지운 이유**를 적는다.

## 2. 로컬 서버
```
node tools/serve.js 8791     # worktree마다 다른 포트. 공용 폴더는 launch 이름 bookshelf(8780)
```
- 주인 화면: `http://127.0.0.1:8791/?demo=1` (가짜 기록 `demo/private.json`, 저장은 메모리에만)
- 방문자 화면: `http://127.0.0.1:8791/`
- 범용판: `http://127.0.0.1:8791/my/`
- 실제 Firebase 쓰기·공개 반영(`publish.js`)은 하지 않는다(효니가 시킬 때만).

## 3. 화면 3폭 숫자 점검
```
node "%USERPROFILE%\.claude\skills\webapp-connect-check\tools\six.mjs" <wt> <out> --q=?demo=1
```
- 폰 375 · 태블릿 768·1180 · PC 1280 · 눕힌 폰 812×375 · 다크 폰. 끝 코드 0이어야 한다(가로 넘침 0, null/undefined/NaN 글자 0, JS 오류 0).
- 숫자만 보고 끝내지 않는다. 바꾼 화면이 찍힌 그림은 직접 연다.
- 바꾼 곳이 탭·창 안이면 `click=선택자 --name=이름`으로 그 화면도 찍는다(창 없는 크롬이라 서비스워커 캐시가 비어 있다).

## 4. 꼭 눌러 볼 흐름 (`?demo=1`, 바꾼 곳과 닿는 것만 + ★는 늘)
진짜 클릭으로 본다(내장 브라우저가 가려져 있으면 창 없는 크롬 `shot.mjs`). 확인 창은 앱 안 `ask` 창이어야 한다.
1. ★ 첫 화면이 뜨고 읽은 책 선반이 보인다. 콘솔 오류 0.
2. ★ 책 하나 눌러 책 창 열기 → 닫기.
3. ★ 탭 넷(읽은 책·내 서재·서평·돌아보기)이 다 열린다.
4. 기록 더하기 → 저장 → 카드 «고치기» → 지우기(`ask` 창).
5. 책 고치기 창: 읽기 상태 바꾸기(읽는 중 ↔ 다 읽음).
6. «⋯ 더 보기» 메뉴가 열리고 Esc로 닫힌다.
7. 합치기 미리보기 → 합치기 → 되돌리기 → 두 책이 처음과 같다.
8. 관리 도구의 일괄 창(빈 칸 채우기·책등 다시 찾기): 찾는 중 닫기 → 바로 다시 열기.
9. 폰 375에서 바꾼 양식 창(`showForm`)을 전부 열어 저장 단추가 보인다.
10. ★ 방문자 화면(`?demo=1` 없이)에 나만 보기·제목 미확인 책·별점이 안 보인다.
11. 범용판 `/my/`가 열리고 책 하나 더하기가 된다(앱 공용 코드를 바꿨을 때).

## 5. 갱신·배포 앞
- 앱 파일을 바꿨으면 `sw.js` VERSION(+ 범용판에 닿으면 `my/sw.js` VERSION)을 올렸는지 본다.
- 병합 뒤 배포 주소 `https://hyonnie-t.github.io/bookshelf/`를 내장 브라우저로 열어 바뀐 것이 보이는지 본다(Ctrl+F5 안내).

## 6. 멈춤 규칙
- 같은 검사가 **세 번 고쳐도 실패하면 멈춘다.** 효니에게 «확인한 것 / 짐작 / 다른 방법»을 나눠 알리고 기다린다(교사업무 CLAUDE.md «같은 방법 두 번 실패면 방법 바꾸기»와 함께: 두 번째 실패 뒤엔 방법을 바꾸고, 세 번째도 실패면 멈춤).

## 7. 검증 도장 (PR 본문 맨 아래, 늘)
```
검증: 시험 13/13 · 화면 six 6크기 넘침0·오류0 · 흐름 ★1·2·3·10 + 4·7 직접 · 못 한 것: 실제 폰 기기
```
- 못 한 검증은 «못 한 것»에 적는다. 아무 검증도 안 했으면 `검증: 없음(이유)`. 나중에 «검증 없음» PR을 찾을 수 있게 하려는 것.
